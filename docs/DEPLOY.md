# Deploying Tharavad (free tier)

The site runs on three free services:

| Part | Service | Free plan limits that matter |
|---|---|---|
| Website (`web/`) | Vercel Hobby | Non-commercial use only |
| API (`api/`) | Render free web service | Sleeps after 15 idle minutes; waking takes up to a minute; 750 free hours a month |
| Database | MongoDB Atlas M0 | 512 MB storage |

Browsers only talk to the website. The website forwards `/api/*` to the API and adds a shared secret (`PROXY_SECRET`) and the visitor's IP, so session cookies stay first-party and rate limits count visitors, not Vercel. The API refuses calls without the secret (except `/health`).

Deploy in this order: database, then API, then website. It takes about 30 minutes.

## 1. Database: MongoDB Atlas

1. Sign up at <https://www.mongodb.com/cloud/atlas> and create a **free M0** cluster. Pick **AWS, Singapore (ap-southeast-1)**: it's next to the API's Render region.
2. **Database Access** → add a database user with a generated password and the role *Read and write to any database*.
3. **Network Access** → add `0.0.0.0/0` (allow from anywhere). Render's free plan has no fixed outbound IP, so there is no narrower option; the user password is the protection.
4. **Connect → Drivers** → copy the connection string. Put the password in it and add the database name before the `?`:

   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/kerala_realty?retryWrites=true&w=majority
   ```

The API creates the collections and loads the 60 demo listings on its first start.

## 2. Two secrets

Run this twice and keep both values somewhere safe (a password manager):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

- The first is `PROXY_SECRET`. It goes on **both** Render and Vercel, with the same value.
- Use the second as `ADMIN_PASSWORD` (or choose your own, 12 characters or more).

`JWT_SECRET` is generated by Render for you.

## 3. API: Render

1. Sign up at <https://render.com> with GitHub.
2. **New → Blueprint**, pick this repository. Render reads [`render.yaml`](../render.yaml) and asks for:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | the Atlas string from step 1 |
   | `PROXY_SECRET` | secret 1 |
   | `WEB_ORIGIN` | leave empty for now; set it to the Vercel URL after step 4 |
   | `ADMIN_EMAIL` | your email; this becomes the first admin account |
   | `ADMIN_PASSWORD` | secret 2 |
   | `GEMINI_API_KEY` | a free key from <https://aistudio.google.com/apikey> (optional: without it the assistant answers with rules only) |

3. Apply. The first build takes a few minutes. Then open `https://<your-service>.onrender.com/health`: it should show `{"ok":true}`. If it shows `{"ok":false}`, the database isn't reachable: check the connection string and Atlas Network Access.

Optional on Render: `GROQ_API_KEY` or `OPENROUTER_API_KEY` as free fallbacks when Gemini is busy.

## 4. Website: Vercel

1. Sign up at <https://vercel.com> with GitHub. **Add New → Project**, import this repository.
2. Set **Root Directory** to `web`. Vercel detects Next.js.
3. Environment variables:

   | Variable | Value |
   |---|---|
   | `API_URL` | `https://<your-service>.onrender.com` (no trailing slash) |
   | `PROXY_SECRET` | secret 1, the same as on Render |
   | `NEXT_PUBLIC_WHATSAPP_NUMBER` | your WhatsApp number with country code, digits only (e.g. `9198xxxxxxxx`). Leave it empty to hide the WhatsApp buttons |
   | `NEXT_PUBLIC_SITE_URL` | only with a custom domain, e.g. `https://tharavad.in` |

4. Deploy. Open the site, then **Sign in** with `ADMIN_EMAIL` and `ADMIN_PASSWORD` and go to **Admin** (`/admin`).
5. Back on Render, set `WEB_ORIGIN` to the Vercel URL.

## 5. After the first deploy

- **Keep the API awake (optional).** In GitHub: Settings → Secrets and variables → Actions → **Variables** → add `SITE_URL` = your Vercel URL. The [keep-warm workflow](../.github/workflows/keep-warm.yml) then pings the site every 10 minutes. One always-on free service uses about 744 of Render's 750 free hours a month, so don't add a second free service. GitHub pauses scheduled workflows after 60 days without commits; turn it back on in the Actions tab. Without it, the first visitor after a quiet spell waits up to a minute; listing pages fall back to the demo data while the API wakes.
- **Admin → Settings:** set the AI limits for the free Gemini tier (default 15 answers per visitor and 800 per day) and the upload caps (default 80 files / 60 MB per account; Atlas M0 has 512 MB in total).
- **Search engines:** the sitemap is at `/sitemap.xml`. Add the site in Google Search Console if you want it indexed.

## Demo accounts in production

They are off by default. To let visitors try each role, set `SEED_DEMO_USERS=true` on Render **before the first start** (on an empty database) and `NEXT_PUBLIC_SHOW_DEMO_ACCOUNTS=true` on Vercel. Production never creates the demo admin.

Be careful: the demo owner and agent accounts share a public password, and the demo listings belong to them. Anyone using those accounts sees the names and phone numbers that real visitors leave in enquiries and visit requests. Keep demo accounts off once real people use the site.

## Before a real launch

These are product decisions, not code:

- The listings, prices and flood layer are demo data and are labelled as such. Replace them before presenting the site as real.
- Have the [privacy notice](../web/src/app/privacy/page.tsx) reviewed by a lawyer, and add a grievance officer and contact address (DPDP Act).
- Vercel Hobby is for non-commercial use, and Render's free instances are meant for hobby projects and testing. A business site needs Vercel Pro and a paid Render instance (which also removes the sleep).
- On the free Gemini tier, Google may use prompts to improve its products. The privacy notice says so. A paid key changes that.

## Checks

```bash
curl https://<your-service>.onrender.com/health               # {"ok":true}
curl -s -o /dev/null -w "%{http_code}\n" https://<your-service>.onrender.com/listings   # 403: direct calls refused
curl -s https://<your-site>.vercel.app/api/listings?limit=1   # JSON: the proxy works
```

## Troubleshooting

| Symptom | Cause |
|---|---|
| Every `/api` call returns 403 "Use the website" | `PROXY_SECRET` differs between Render and Vercel. Redeploy Vercel after changing it (it's read at request time, but env changes need a redeploy) |
| Render build fails with `tsc: not found` | The build command must keep `--include=dev` |
| `/health` returns `{"ok":false}` | Atlas unreachable: wrong password in the string, or Network Access missing `0.0.0.0/0` |
| Can't sign in as admin | `ADMIN_PASSWORD` under 12 characters (see the Render log), or the account already existed with another password |
| Listing pages slow on first visit | The API was asleep; see "Keep the API awake" |
